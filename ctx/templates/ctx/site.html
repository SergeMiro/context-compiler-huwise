Context Compiler

A Huwise / Opendatasoft data portal compiled into tested context for AI agents. Development portal: {{ domain }}.

A portal already gives agents an API for every dataset. What agents lack is context: which of five similar datasets is the right one, what a field means, how its values are written. This project compiles the portal's catalog into one short card per dataset, serves the cards over MCP with search boosted by real usage, and measures with a golden set whether the cards make an agent answer better.

Try it

Live, read-only MCP server (streamable HTTP): https://context.smiro.dev/mcp. Tools: find_dataset, explain_dataset, query (ODSQL is checked against the real schema before it reaches the portal).

claude mcp add --transport http context https://context.smiro.dev/mcp --header "X-Domain: {{ domain }}"

Then ask: « Combien de collèges publics en Côte-d'Or ? » → 58.

For agents without MCP: llms.txt and {{ pages }} pages in datasets/. Source: github.com/SergeMiro/context-compiler-huwise.

Traps an agent falls into

Writing 30 reference queries by hand failed 11 times on the first run, on exactly these:

trapexample
one department, three formatsCôte-d'Or is '021' in the directory, '21' in IPS datasets, "COTE D'OR" as a label
years stored as datessession='2025' → API type error; year(session)=2025 works
numbers stored as textavg(ips) fails on IPS écoles; order_by ips_etab desc sorts as strings
case differsacademie='DIJON' vs libelle_academie='Dijon'

Cards carry real sample values for key fields and a hint for every date field, so the agent reads the format instead of guessing it.

Architecture

COLD PATH (commands / Celery; the only place an LLM is ever called)
  Explore API --scan--> Portal / Dataset / Field   (MariaDB = single source of truth)
                          | compile (deterministic)
                          v
                        Card v1..vN  <-- kept ContextEdit
             +------------+-------------+
             v            v             v
        ES `cards`     Neo4j          llms.txt + datasets/<id>.md
  eval:    EvalCase -> agent -> EvalRun / EvalResult
  improve: failures -> LLM proposes edit -> compile -> eval -> kept | reverted

HOT PATH (MCP, no LLM, no writes except the ToolCall log)
  find_dataset(question) -> ES (filter + routing by portal) + usage boost -> short cards
  explain_dataset(id)    -> full card + joinable datasets + lineage (Neo4j)
  query(id, odsql)       -> validator -> Explore API (client key passed through, limit <= 100)

Stack, the same as Huwise: Django + DRF, MariaDB, Celery + RabbitMQ, Elasticsearch, Neo4j, MCP Python SDK. find_dataset p95 13 ms, explain_dataset p95 23 ms in process.
